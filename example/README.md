# LASTFit Release Examples

The examples provide compact, versioned assets for inspecting and exercising
the solver modes described in the LASTFit Part I manuscript. Each case keeps
configuration, reference grid, restart, and representative output data
together without duplicating full production time histories.

## Directory Convention

```text
case_name/
  Config.cfg       Solver namelist read at runtime
  grid/            Reference grid generated by the solver
  restart/         Flow and fitted-shock restart files
  output/          Read-only reference output
  README.md        Case-specific staging and scope
  SHA256SUMS       Checksums for configuration and numerical data
```

The solver generates a grid from `Config.cfg`; files under `grid/` are provided
for inspection and comparison. A live calculation writes to `INIT/`, `JACO/`,
`RESU/`, `Pert/`, and `LNSResults/` in its working directory.

## Staging a Run

Build `src/SFSolver`, create an isolated working directory, and copy the case
configuration into it. For a nonlinear continuation, stage `restart/*` under
`RESU/`. For an LNS run, stage the nonlinear base flow under `RESU_STEADY/`.

```bash
mkdir -p run/{INIT,CheckFiles,JACO,RESU,RESU_STEADY,LNSResults,Pert}
cp src/SFSolver run/
cp example/<case>/Config.cfg run/
```

Use `npx0 * npz0` MPI processes. The main README and each case README provide
the exact command and restart location.

## Integrity and Scope

Run `sha256sum -c SHA256SUMS` from a case directory before using its binary
data. Each manifest covers `Config*.cfg` plus files in `grid/`, `restart/`, and
`output/`; documentation files are intentionally excluded.

The examples are release records, not a substitute for a versioned archive of
all production-grid histories. Where a compact release grid differs from the
manuscript production grid, the case README states that boundary explicitly.
